## Floor of the emitted code

The generated container needs the global `AggregateError`. In TypeScript terms that is `lib` `es2021`, and nothing else above `es2020`.

- When it is emitted. The container throws one `AggregateError` when a disposal fails, in `destroy()` and, with test overrides on, in the reconfiguration (`packages/core/src/generator/LifecycleEmitter.ts:655`, `packages/core/src/generator/LifecycleEmitter.ts:760`). Both are emitted only when the graph has at least one disposal slot. A slot is a registration that is neither transient nor borrowed and that either has a `dispose` method, has a method keyed by `Symbol.dispose` or `Symbol.asyncDispose`, or is a factory (`packages/core/src/generator/LifecycleEmitter.ts:536-543`). A container with classes and values that own nothing to release never names `AggregateError` (`packages/core/tests/generator/t09-d3-helpers.test.ts:191-193`, `packages/core/tests/generator/t09-d3-helpers.test.ts:497-502`).
- When it is checked. The name matters where the output is type-checked against the consumer's `lib`: the ts-patch transformer path (`packages/unplugin/tests/t23-inline-bindings.test.ts:22-25`) and a separate generated file. A bundler path strips types and runs no lib check. A project that type-checks the output with a lib below `es2021` gets `TS2304: Cannot find name 'AggregateError'` for a container that has a disposal slot. Add `es2021` or later to `lib`. A `target` of `ES2021` selects `lib.es2021.full.d.ts` (checked with `ts.getDefaultLibFileName` of the TypeScript 5.9.3 this repository installs, `package.json:42`).
- What the runtime needs. The engine that executes the output must define `AggregateError`. `node -e "console.log(typeof AggregateError)"` prints `function` under Node v22.23.2, the local Node of this check. No other engine was run for this page.
- What a test proves. Emitted code with a disposable, async factories, open and closed, full and minimal, both emitters, type-checks with no diagnostic at `lib.es2021.d.ts`; the same output at `lib.es2020.d.ts` reports exactly `TS2304` for `AggregateError` and nothing else (`packages/core/tests/generator/t09-d3-helpers.test.ts:479-504`). A disposable that throws makes `destroy()` reject with an `AggregateError` that holds every failure (`packages/core/tests/generator/t09-d3-helpers.test.ts:220-238`).
- What CI runs. The test job runs on Node 20 and Node 22 (`.github/workflows/ci.yml:15`) and executes `pnpm test:coverage` (`.github/workflows/ci.yml:33-34`), which includes both tests above. No workflow file names a browser runner (a search of `.github/workflows` for playwright, chromium, puppeteer, jsdom and happy-dom found none). The consumer types fixture sets `target` `ES2022` (`tests/consumer-types/positive/tsconfig.json:4`). The only run at a lib below `es2021` that this page knows is the `es2020` control above.
- Disposal protocols. The container reads `Symbol.asyncDispose` and `Symbol.dispose` from `Symbol` through an intersection type (`SymbolConstructor & { dispose?: symbol; asyncDispose?: symbol }`), when a value is disposed and when the class is defined, so the output names no property that `lib` `es2021` lacks (`packages/core/src/generator/LifecycleEmitter.ts:40-41`, `packages/core/src/generator/LifecycleEmitter.ts:78-82`). Its type for `[Symbol.asyncDispose]` is a conditional on `SymbolConstructor`: with `lib: ["ESNext.Disposable"]` the member exists, with any other lib it is an empty object type and no global type of the disposable lib is named (`packages/core/src/generator/LifecycleEmitter.ts:90-93`, `packages/neosyringe/src/types.ts:21-23`).
- What a test proves for the protocols. A container with a symbol selector (a factory singleton and an async factory) type-checks with no diagnostic at `lib.es2021.d.ts`, and at `lib.es2020.d.ts` it reports `TS2304` for `AggregateError` and nothing else (`packages/core/tests/generator/t21-floor.test.ts`, `T21-P18`). The consumer fixture with `lib: ["ES2022", "ESNext.Disposable"]` compiles `await using` against the source and against a packed archive, and the fixture with no disposable lib still compiles (`tests/ci/t21-disposal-types.test.ts`, `T21-P20`). The transformed Program compiles with and without the lib (`packages/unplugin/tests/t21-disposal-types.test.ts`, `T21-P23`, `T21-P24`).
- What the runtime needs. `await using` itself needs a runtime with `Symbol.asyncDispose`. `node -p "typeof Symbol.dispose + ' ' + typeof Symbol.asyncDispose"` prints `symbol symbol` under Node v22.23.2, the local Node of this check, and `typeof SuppressedError` prints `undefined` there, so the compiled `await using` test uses the helper that TypeScript emits (`packages/core/tests/generator/t21-disposal-runtime.test.ts`, `T21-P12`). The test is skipped on a Node without `Symbol.asyncDispose`. Node 20 was not run for this page; the CI matrix runs it (`.github/workflows/ci.yml:15`). Without the symbol the container loads and `destroy()` works (`T21-P11`).
- The new consumer fixtures run in CI from the source and from the packed archive, and from the source in the release verification (`.github/workflows/ci.yml:100-105`, `.github/workflows/ci.yml:112-117`, `.github/workflows/release.yml:68-73`).

## Not qualified

- Node 24. The CI matrix lists 20 and 22 only (`.github/workflows/ci.yml:15`).
- Any TypeScript version other than the one this suite installs. The root dev dependency is `typescript` `^5.9.3` (`package.json:42`). The peer range `>=5.0.0` (`packages/core/package.json:35`) is not a test matrix.
- Windows. The CI jobs in this workflow use `ubuntu-latest` (`.github/workflows/ci.yml:12`). No file under `.github/workflows` sets `windows-latest`. `packages/unplugin/tests/t11-pipeline.test.ts:433` feeds Windows-shaped strings to the transform on the machine that runs the suite. That is not a Windows run.
- `.mts` and `.cts` as container entries. A marker file whose name ends in `.mts` throws (`packages/unplugin/tests/t11-pipeline.test.ts:463-465`). A plain `.mts` or `.cts` file is left unchanged (`packages/unplugin/tests/t11-pipeline.test.ts:468-469`).
- Bundled `.d.ts`. The manifest step asks for per-file declaration emit and says bundled declarations are not supported (`packages/core/src/generator/tokensManifest.ts:23-24`).
- Sourcemaps of a published package. `packages/unplugin/tests/t11-sourcemap.test.ts:110` checks a transform sourcemap. It does not check a map file shipped in a published tarball.
- CRLF vs LF checkouts and edits above the call give different internal names (declarationId is the call offset) (`packages/core/src/analyzer/shared/artifactIdentity.ts:231-233`).
- Webpack, esbuild, and rspack. This plugin clears the collision registry only from the Rollup and Vite hook objects (`packages/unplugin/src/index.ts:191-205`). The option type names the other entry points (`packages/unplugin/src/index.ts:11`) and registers no close hook for them.

## Files outside the package

Internal names are reproducible across checkouts only for a file under a package root or the TypeScript project root. That file keeps the project-relative path (`packages/core/src/analyzer/shared/artifactIdentity.ts:236-239`, `packages/core/tests/shared/artifactIdentity.test.ts:180`, `packages/core/tests/generator/t10-two-root.test.ts:89`).

A file outside every known root records `unrooted:` plus its normalized absolute path (`packages/core/src/analyzer/shared/artifactIdentity.ts:240`). The path uses forward slashes, keeps the drive letter, and keeps the original case (`packages/core/src/analyzer/shared/artifactIdentity.ts:180-196`, `packages/core/tests/shared/artifactIdentity.test.ts:239`, `packages/core/tests/shared/artifactIdentity.test.ts:244`). A `?query` or `#hash` is removed, and `.` or `..` segments collapse, so two spellings of one file share one descriptor (`packages/core/src/analyzer/shared/artifactIdentity.ts:169-173`, `packages/core/src/analyzer/shared/artifactIdentity.ts:189-191`, `packages/core/tests/shared/artifactIdentity.test.ts:234-236`, `packages/core/tests/shared/artifactIdentity.test.ts:246`). Two distinct files do not share it (`packages/core/tests/shared/artifactIdentity.test.ts:209-221`, `packages/unplugin/tests/t10-session-identity.test.ts:198-200`). That absolute path is not reproducible across machines. A drive-letter path is resolved with the win32 path API, so it is not joined to the process directory (`packages/core/src/analyzer/shared/artifactIdentity.ts:147-149`, `packages/core/tests/shared/artifactIdentity.test.ts:240`).

`artifactDescriptor` still rejects an absolute path, a parent segment, a dot segment, and a drive letter on a rooted relative path (`packages/core/src/analyzer/shared/artifactIdentity.ts:44-51`). The `unrooted:` marker is the only accepted absolute form (`packages/core/src/analyzer/shared/artifactIdentity.ts:24-31`). A marker that is not a clean absolute is refused (`packages/core/tests/shared/artifactIdentity.test.ts:70-75`). A path that would leave a root is dropped (`packages/core/src/analyzer/shared/artifactIdentity.ts:204-206`). There is no silent `..` in a rooted name (`packages/core/tests/shared/artifactIdentity.test.ts:171`). A `#<tsconfigDir>` suffix is added only when a project root is already known (`packages/core/src/analyzer/shared/artifactIdentity.ts:227-230`). No project root means no suffix. The collision registry still refuses two different sources on one key (`packages/core/src/analyzer/shared/artifactIdentity.ts:106-111`). An injected hash still throws (`packages/unplugin/tests/t10-session-identity.test.ts:180`). Two packages with no `name` still throw (`packages/unplugin/tests/t10-session-identity.test.ts:217`).
