# Topic 20: the cost of an alias

What a read of an alias (`useExisting`) costs next to a relay factory and next to a read of the target. This is a measure of one machine and one run. It is not a promise: nothing here says an alias is faster than anything on another machine, another Node or another container.

## What is measured

`tests/bench/alias-cost.mjs` builds each container with the Analyzer and the Generator of the built packages and refuses to start when that dist is older than `packages/core/src` (`tests/bench/alias-cost.mjs:60`): run `pnpm build` first. It writes each compiled container to a file and runs every case in a worker process of its own (`tests/bench/alias-cost.mjs:171`, `tests/bench/alias-worker.mjs`), the way `runtime-cost.mjs` does, so no case shares a `resolve` call site or a JIT state with another. In the worker, a sample is one batch of 1 000 000 `box.resolve(token)` reads of the last token, in ns per read: two warm-up batches dropped, then five samples. The run is three rounds; in each round every case runs once in a fresh process, and the order of the cases rotates every round, so a drift of the machine does not belong to one case. A case has 15 samples. The median is the figure, the minimum is shown beside it.

Before any batch, the worker checks its case: the token answers an `Engine`, a singleton answers the object of the target, a transient answers a new object at every read (`tests/bench/alias-worker.mjs:18`). A case that fails the check stops the script.

The report carries the git SHA and a dirty flag (`git status --porcelain` not empty), the load average before and after, and the machine.

The three shapes, on class tokens `P0`, `P1`, ... and a target `Engine`:

- **target**: `resolve(Engine)`.
- **alias xN**: a chain of N aliases, `{ token: P0, useExisting: Engine }`, `{ token: P1, useExisting: P0 }`, and so on. `resolve(P{N-1})`.
- **relay xN**: the same chain written as factories, `{ token: P0, useFactory: true, dependencies: [Engine], ownership: 'borrowed', provider: (ctx) => ctx.resolve(Engine) }`, with `lifecycle: 'transient'` when the target is. `resolve(P{N-1})`.

Two containers: `full` profile in open mode, and `minimal` profile in closed mode (the alias is the root). Singleton and transient targets. N is 1 and 10.

## What the numbers say, and what they do not

- A singleton read costs about the same through an alias, through a relay factory and directly: a relay of a singleton is a cached value, so the factory runs once. At depth 1 the figures are within 10 % of the target in both containers. At depth 10 they are 1.32 (alias) and 1.37 (relay) times the target in the full/open container (7.7 and 8.0 ns against 5.8) and 1.03 in the minimal/closed one.
- A transient read through a relay factory runs a factory per link, and each factory resolves the next: 45.4 ns for one link and 262.6 ns for ten in the full/open container, against 5.1 and 6.0 ns for an alias. An alias of a transient is not free next to the target: 1.50 times at depth 1 and 1.74 times at depth 10 in the full/open container (3.4 ns for the target), and 1.04 and 1.01 in the minimal/closed one.
- The generated text grows with the chain for a relay (12 835 bytes for one link and 36 442 for ten, in the minimal/closed container) and little for an alias (7 456 and 8 248): the last column.
- The difference between depth 1 and depth 10 of an alias in the full/open container (5.7 against 7.7 ns for a singleton, 5.1 against 6.0 for a transient) was not investigated: this page does not say why.
- A first version of this bench ran the twenty cases in one process, through one shared `batch(box, token)` function, and found a singleton target at about 11 ns and an alias of a transient at about 1.02 times the target. Those numbers carried the bias of a call site that saw twenty different containers. They are dropped: they are not comparable with the table above, and nothing here relies on them.
- This is one run. The page did not repeat it, so it knows nothing of the spread from one run to the next, and it does not claim that an alias is faster than the target at depth 1.

Not measured: a larger container than eleven registrations, an async target, a parent target, the cost of the analysis, a run on a clean tree, and any machine other than the one above. The size column is the text of the generated container, not a bundle.
