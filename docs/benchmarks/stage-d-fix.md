# Étape D : régressions de `full` en mode `open`

Cette page dit pourquoi `full` en mode `open` est plus lent à froid et plus gros à `a3562b1` (étape D) qu'à `ba192b4`, ce qui a été changé et ce qui reste. Les données brutes sont dans `docs/benchmarks/data/stage-d-fix/`. Chaque nombre cite une ligne d'un fichier de ce dossier, d'une source du dépôt ou d'une commande en lecture seule citée avec sa sortie. Les médianes en ns sont arrondies à 0.1 dans ce texte. Les sources citées sans nom de commit sont celles de l'arbre de la correction.

Les mesures `proto1` et `proto2` sont des essais rapides de prototypes, avec 3 processus et sans campagne. Elles ne mesurent pas le code de l'arbre. Cette page ne revendique aucun gain et ne certifie aucune performance : le verdict est celui de la campagne finale, dans le dernier chapitre.

Quatre constats, indépendants. Les trois premiers viennent de la forme du code émis. Le quatrième dit qu'une régression citée n'est pas reproduite.
